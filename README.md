# 婚礼请柬网站 · 陶林伟 & 肖佩韦

一个单页静态婚礼请柬网站，包含婚礼信息展示和出席登记表单。

## 页面内容

- 婚礼请柬主视觉：`images/invitation.jpg`，一张完整设计好的请柬图片（标题、新人姓名、日期、
  农历日期、签到合影/晚宴仪式时间、婚礼地址等信息都画在图里）
- 图片下方是一条装饰性的走动动画（英短蓝白、金吉拉白、美短三只猫 + 新人牵手走过）
- 出席登记表单：姓名、是否出席、出席人数、所在城市（默认"上海"）、备注

## 目录结构

```
.
├── index.html          # 网站唯一页面，样式与交互均内嵌在此文件中
├── images
│   └── invitation.jpg  # 请柬主视觉图片
├── functions
│   └── api
│       └── rsvp.js     # EdgeOne Pages Function，处理登记表单提交（读写飞书多维表格）
└── README.md
```

> 部署时务必把 `images/` 文件夹和 `index.html` 一起上传/提交，漏传会导致图片 404
> （之前踩过这个坑）。

## 出席登记表单说明（存到飞书多维表格）

访客在网页里直接填写登记表单，点击"提交登记"后，请求会发到本项目自带的
`/api/rsvp` 边缘函数，由这个函数读写你自己的飞书多维表格（相当于一个在线数据库）：

- **新增**：第一次用某个姓名提交，会在表格里新建一行
- **修改**：之后再用同一个姓名重新提交，会自动覆盖更新那一行的内容（不会产生重复记录）

> 注意：目前用"姓名"精确匹配作为唯一标识。如果两位宾客正好同名，
> 后填的会覆盖先填的那条记录。如果你担心重名，可以告诉我，改成用"姓名+手机号"
> 一起作为标识即可。

### 你需要做的前置准备（一次性）

1. **创建飞书自建应用**
   - 打开 [open.feishu.cn](https://open.feishu.cn) → 开发者后台 → 创建企业自建应用
     （个人飞书账号也可以创建，应用默认只能被你自己这个"团队"使用，够用）
   - 在应用的"凭证与基础信息"里拿到 `App ID` 和 `App Secret`
   - 在应用的"权限管理"里搜索并开通多维表格相关权限（`bitable` 相关的读写权限），
     然后发布/启用应用

2. **创建多维表格（Base）**，添加以下字段，字段名必须和下面完全一致：
   - `姓名`（单行文本）
   - `是否出席`（单选，选项：出席 / 不出席）
   - `出席人数`（数字）
   - `所在城市`（单行文本）
   - `备注`（多行文本）

3. **把刚才创建的应用添加为这张表的协作者**（且给"可编辑"权限），
   否则应用没法写入数据。多维表格右上角"..." → 协作者与权限 → 添加协作者，
   把应用加进去。

4. **拿到 `app_token` 和 `table_id`**：打开这张多维表格，看浏览器地址栏，
   形如：
   ```
   https://xxx.feishu.cn/base/<这一段是 app_token>?table=<这一段是 table_id>
   ```

5. **在 EdgeOne Pages 项目里配置环境变量**（不要把这些值写进代码仓库）：
   - `FEISHU_APP_ID`
   - `FEISHU_APP_SECRET`
   - `FEISHU_APP_TOKEN`
   - `FEISHU_TABLE_ID`

   在 EdgeOne Pages 控制台 → 你的项目 → 设置 → 环境变量里添加，保存后重新部署一次即可生效。

配置好以上几步，网页上的登记表单就会自动把数据写进你的飞书多维表格，
你随时打开表格就能看到最新的登记名单，也能直接在表格里筛选、统计、导出。

## 本地预览

直接用浏览器打开 `index.html` 可以看到页面样式，但登记表单需要 EdgeOne Pages
的边缘函数环境才能跑通（本地静态打开无法调用 `/api/rsvp`）。

## 部署到 EdgeOne Pages（推荐：绑定 GitHub 自动部署）

1. 把本仓库推送到你自己的 GitHub 账号下（已完成，仓库地址见 GitHub 页面）。
2. 登录腾讯云 EdgeOne Pages 控制台，选择"创建项目" → 选择"导入 Git 仓库"，
   授权并选择这个 GitHub 仓库。
3. 构建配置：本项目是纯静态 HTML + Pages Functions，**不需要构建命令**，
   输出目录填根目录（`/` 或留空）即可；`functions/` 目录会被 EdgeOne 自动识别为边缘函数。
4. 按上面"前置准备"第 5 步配置好环境变量。
5. 绑定完成后，以后每次把改动 push 到 GitHub 的这个仓库，EdgeOne 会自动重新部署，
   不用再手动上传文件。

### 如果使用"直接上传"方式部署

需要把 `index.html`、`images/` 和 `functions/` 三者一起上传，且要确认 EdgeOne Pages
的"直接上传"方式支持部署 Pages Functions（不同上传方式对 Functions 的支持可能不同，
如果发现表单提交没反应，建议改用"绑定 GitHub 仓库"的方式部署）。

## 修改内容

  也可以把要改的内容发给我，由我代为修改后重新推送。
