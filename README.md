# 婚礼请柬网站 · 陶林伟 & 肖佩韦

一个单页静态婚礼请柬网站，包含婚礼信息展示和出席登记表单。

## 页面内容

页面从上到下的顺序：

1. **婚礼请柬主视觉**：`images/invitation.jpg`，一张完整设计好的请柬图片（标题、新人姓名、
   日期、农历日期、签到合影/晚宴仪式时间、婚礼地址等信息都画在图里）。
   **可以点击放大**，页面也允许双指缩放，方便年长的宾客看清（页面上不作文字提示）
2. **出席登记表单**：姓名、是否出席、出席人数（下拉，最多 5 人）、备注
3. **走动动画**：手绘线条风格的小动画（详见下方"走动动画"）
4. **图片展示区**：婚纱照 + 中式礼服，点任意一张可放大查看，支持左右切换和 Esc 关闭
5. **页尾**：新人姓名与日期

> 页面**没有**禁用缩放（`<meta viewport>` 里不要再加 `user-scalable=no`），
> 否则年长宾客没法放大看细节。

## 走动动画

页面中段有一条手绘线条风格的小动画，四个角色会以不同速度、不同时间间隔循环走过：

| 角色 | 特征画法 |
| --- | --- |
| 英短蓝白 | 圆耳朵、身上一条分色曲线 |
| 新郎 & 新娘 | 新郎西装领结、新娘长发婚纱捧花，两人牵手 |
| 金吉拉白 | 身体轮廓带绒毛凸起、大圆眼睛、蓬松羽状尾巴 |
| 美短 | 额头 M 纹、身上虎斑条纹、尾巴环纹 |

实现要点（都在 `index.html` 的 `<style>` 与内联 SVG 里）：

- **图形**：纯内联 SVG 路径，没有外部图片。头部/身体重叠处用白色填充（`.fw` 类）遮挡后面的线条，
  避免出现接缝
- **走路**：每条腿是一个 `.leg` 路径，用 CSS `transform-box:fill-box` + `transform-origin:50% 0`
  让它绕"胯部"来回旋转；`.leg.b` 用反相的关键帧，形成左右腿交替的连续步态
- **其他细节**：尾巴摆动（`.tail`）、婚纱裙摆轻晃（`.skirt`）、整体上下轻微起伏（`bob`）
- **无障碍**：系统开启"减少动态效果"时，整条动画会自动隐藏

想调整节奏，改每个 `.sprite` 上的 `--dur`（走完全程的时长）和 `--delay`（出场延迟）即可。

## 微信分享卡片

分享链接到微信时会显示一张卡片，包含标题、描述、缩略图三部分，这些都在
`index.html` 的 `<head>` 里配置好了：

- 标题、描述在 `<head>` 的 `og:title` / `og:description` 里，改文案直接改这几行
- 缩略图是婚纱照裁出的脸部特写 `images/share.jpg`（400×400、约 21KB —— 图太大微信会直接跳过）
- 另外在 `<body>` 最前面藏了一张同样的图，因为有些抓取程序不读 meta，只取 HTML 里的第一张图

> **换域名后必须改**：`og:url`、`og:image`、`itemprop=image`、`link rel=image_src`、
> `twitter:image` 这几行写的是完整绝对地址。微信基本不认相对路径，域名变了就要一起更新。

需要知道的限制：微信对普通链接**并不保证**读取 og 标签，分享卡片是它自己的爬虫按
启发式规则生成的。想要完全控制标题/描述/图标，官方途径是接入微信 JS-SDK，
而那需要有公众号并配置 JS 安全域名。上面这些做法是把命中率拉满，但没法保证 100%。

微信抓取结果缓存较久。改完重新部署后卡片没更新的话，在网址后面加个参数
（比如 `?v=2`）换成一个"新链接"再分享，或者等缓存过期。

## 背景音乐

页面支持一首循环播放的背景音乐，右上角有开关按钮。

音频文件是 `audio/bgm.mp3`（新郎自己弹的钢琴录音，从视频里提取的音轨：
单声道 80kbps、2 分 58 秒、1.7MB；已剪掉录音开头 1.2 秒的静音和结尾的 App 水印语音，做过响度归一化，开头不做淡入，结尾留 1.5 秒淡出以免循环回头时爆音）。
想换曲子就替换这个文件；如果文件不存在，按钮会自动保持隐藏，页面一切正常。

几点需要知道的：

播放时机：

1. 页面主要内容加载完（`load` 事件）后才开始下载音频，**不与请柬图抢带宽**
2. 缓冲到能一口气播完（`canplaythrough`）时自动开始播，中途不会卡顿
3. 直接以 45% 音量起播 —— 曲子本身起音就很轻，不需要额外做渐强
4. 如果浏览器拦截了自动播放，则在访客**第一次轻触页面**时再尝试一次

- **浏览器普遍禁止无交互自动播放带声音的媒体**，这是硬性限制、绕不过去。
  **iPhone（Safari / 微信 iOS 版）一定不会自动播放**，必须等访客碰一下屏幕；
  微信安卓版走 `WeixinJSBridgeReady`，通常能直接自动播放
- iOS 还有一个坑：**用户交互之前根本不会缓冲音频**，所以 `canplay` 可能一直不触发。
  因此按钮默认就显示（只有确认文件加载失败才隐藏），交互监听也会一直保留到
  真正出声为止 —— 否则第一次轻触时音频还没就绪，那一次就白白浪费了
- 访客手动按暂停后，不会再被自动接管，除非他自己再按一次
- 循环播放，右上角按钮可随时开关
- 建议把 mp3 压到 3MB 以内（当前 1.3MB），否则移动网络下载很慢

> 目前用的是自己演奏的录音。需要留意的是，演奏录音归你，但**乐曲本身的版权仍属原作者**，
> 而这个页面是公开可访问的。婚礼请柬这种私人用途一般不会有人追究，但严格说属于灰色地带。

## 图片展示区

照片都放在 `images/gallery/`，按用途命名，**改图片只要替换同名文件即可**，
不用动 HTML：

| 文件 | 内容 |
| --- | --- |
| `pNN.jpg` | 婚纱照，共 22 张（`p00.jpg` 是首图，两人正面全身）。编号按显示顺序递增，但**中间有跳号**（删掉过一批照片，为避免和之前沟通时的编号对不上，保留了原编号没有重排） |

排版说明：

- 用 CSS Grid 两列排布，`index.html` 里每张图带一个比例类：
  `r32`（横 3:2）、`r23`（竖 2:3），`full` 表示跨满两列
- **横幅照片通栏，竖幅照片两两成对**，两者交替出现，避免一路平铺下来；
  另外挑了几张竖幅做通栏当视觉重点
- 编号大致等于显示顺序（有跳号），想调整顺序改 `index.html` 里 `<button class="tile">` 的排列即可
- 增删照片后要重新编排：横幅通栏、竖幅两两成对，两者尽量交替
- **加载策略**：不用浏览器原生 `loading="lazy"`（它会一次并发抓好几张），
  改成自建队列：同一时刻只下载一张，且始终挑文档顺序最靠前的那张，
  滚动到附近才排队（提前一屏）。图片写在 `data-src` 上，由 JS 赋给 `src`
- 加载失败会退避重试 3 次；仍失败就跳过，不会卡住后面的图
- 换了图但文件名不变时，**记得把 `index.html` 里的 `?v=` 版本号加一**，
  否则宾客手机上的缓存会一直显示旧图（曾经踩过：部分人看到的是旧的模糊版）
- 点任意一张会打开灯箱大图，可用左右箭头/键盘方向键切换，点背景或按 Esc 关闭

所有图片长边压到 1600px、质量 0.88（请柬图 1700px / 0.9）。

关于体积与带宽：全部看完 + 听音乐，单个访客最多下载约 **12 MB**。
按 300 位宾客算约 3.4 GB，只占 100GB 月流量的 3.4%（1000 人也才 11%）。
所以画质留了充足余量，不必为省流量牺牲清晰度；反过来，如果以后要再加很多照片，
可以按这个方法重新估算。
新加照片时建议也先压到这个量级，否则手机流量打开会很慢。

## 出席登记表单

访客填完表单点"提交登记"后，请求发到 Cloudflare Worker 的 `/api/rsvp`，
记录存进 Cloudflare D1（一个免运维的 SQLite 数据库）。

表单不再单独收集"是否出席"——提交表单本身就代表出席。

- **新增**：第一次用某个姓名提交，新建一条记录
- **修改**：之后用同样的姓名再提交一次，会覆盖那条记录（不会产生重复），
  首次登记时间会保留
- 人数超出 1–5 会被自动收进范围，姓名为空会被拒绝

> 用"姓名"作为唯一标识。万一两位宾客同名，后填的会覆盖先填的。
> 后台导入时遇到同名会明确标出"疑似重名"并且默认不勾选，由人来确认。

### 连不上服务器时会怎样（最关键的一块）

国内访问境外接口本来就不稳，所以这条路必须有兜底：

1. 提交会自动重试两次（10 秒 + 8 秒）
2. 两次都失败，页面**自动展开「备用登记通道」**：
   - 国内备用表单的链接（`FALLBACK_FORM_URL`，会预填姓名和人数）
   - 「复制登记信息」按钮，复制出 `【出席登记】姓名：…｜人数：…｜备注：…`，
     宾客直接微信发给新人
   - 新人微信二维码（放成 `images/wechat-qr.png` 就显示，没放就不显示，不会留破图）
3. 宾客看到的永远是固定中文文案，不会出现 `Failed to fetch` 这类看不懂的东西

备用通道收到的登记，在后台「从备用通道导入」里粘进去，会**写回同一个服务器**，
所以名单始终只有一份，不会一半在这、一半在微信聊天记录里。

备注那一栏问的是饮食禁忌，属于健康信息，所以**故意不**预填进备用表单的 URL——
免得留在第三方的访问日志和微信的链接扫描里。

### 三个配置项

`index.html` 顶部 `<script>` 里：

```js
var RSVP_ENDPOINT     = '';   // Worker 地址，结尾不要带斜杠
var FALLBACK_FORM_URL = '';   // 国内备用表单地址，留空则不显示这一层
var CONTACT_LINE      = '';   // 备用通道里显示的联系方式，留空则不显示
```

`admin.html` 顶部还有一个 `RSVP_ENDPOINT`，填成同一个地址。

> `RSVP_ENDPOINT` 留空是刻意的默认值：这时页面不去连任何服务器，宾客点提交后
> 直接看到备用通道。宁可这样，也不要对着一个不存在的接口白转圈、最后什么都没登记上。

## 部署结构

页面和接口分开部署，因为 GitHub Pages 只能托管静态文件、跑不了后端：

```
GitHub Pages（绑 taolinwei.com）        Cloudflare Worker + D1
https://taolinwei.com/                  https://rsvp.taolinwei.com/
Wedding-Invitation/
├── index.html        ── 调用 ──▶       ├── POST /api/rsvp   写入登记（公开）
├── admin.html                          ├── GET  /api/list   读取名单（要口令）
├── images/ audio/                      └── GET  /health     存活探测 + 连接预热
└── favicon / manifest                       （数据在 D1，每天备份到私有仓库）
```

> **域名怎么绑（这一步很容易搞反）**：正式地址是
> `https://taolinwei.com/Wedding-Invitation/`，末尾带 `/Wedding-Invitation` 这一段。
> 这个路径前缀只有在**把 `taolinwei.com` 绑给 `Linwei94.github.io` 那个用户主页仓库**
> 时才成立——绑好之后，你名下所有项目仓库都会挂在 `taolinwei.com/<仓库名>/` 下面。
>
> **不要**在本仓库放 `CNAME` 文件。在项目仓库里放 `CNAME=taolinwei.com` 的效果是
> 把这个项目挂到 `taolinwei.com/` 根目录，`/Wedding-Invitation` 这段路径就没了，
> 而且会和用户主页仓库抢同一个域名。所以本仓库的 Pages 保持默认设置即可。

### 一、页面部署到 GitHub Pages

1. 代码推到 `main` 分支即自动发布
2. 仓库 Settings → Pages → Source 选 `main`、目录 `/ (root)`
3. `.nojekyll` 让 GitHub 原样输出文件，不要删
4. 几分钟后能在 `https://taolinwei.com/Wedding-Invitation/` 打开

### 二、先做国内实测，再建接口

我**没有网络，没有验证过任何一条国内可达性**。Cloudflare 在国内大致是
"通常能连上、有时很慢"，必须你用国内手机实测。手机流量、关 WiFi、关 VPN：

| # | 测什么 | 怎么测 | 判断 |
| --- | --- | --- | --- |
| 1 | 走哪个机房 | 打开 `https://rsvp.taolinwei.com/cdn-cgi/trace` 看 `colo=` | HKG/NRT 好；LAX/SJC/SEA 说明绕到了美西，每次提交多跨一次太平洋 |
| 2 | 能不能解析 | 用 `114.114.114.114` 解析这个域名 | 拿到真实 Cloudflare IP 说明没被污染。这一步区分"被墙"和"只是慢" |
| 3 | 普通浏览器 | 打开 `/health` | 返回 JSON 就是通的 |
| 4 | **微信里** | 把 `/health` 发给"文件传输助手"，**在微信里点开** | 测的是微信 X5 内核；出现"已停止访问该网页"说明域名被微信拦了 |
| 5 | 真提交一次 | 微信里打开正式页面，填表提交，**掐表** | 2 秒内好；反复超过 5 秒宾客会放弃 |
| 6 | 最坏情况 | 晚上 21:00–22:30 再测一遍第 5 项，最好三家运营商都试 | 只有白天能用的站，婚礼当周会出事 |

还要测**页面本身**：把 `https://taolinwei.com/Wedding-Invitation/` 发到微信里打开，
看能不能打开、请柬图几秒出来。这条是任何后端方案都救不了的；如果页面本身在国内
打不开，备用表单就得当"最后一道防线"，所以它的表单说明里要写上日期、地点、详细地址。

> 顺带一个好处：绑了自己的域名之后，宾客拿到的链接里不再有 `github.io`。
> GFW 的 DNS 污染是按域名匹配的，`github.io` 正是那个容易被污染的名字，
> 换成 `taolinwei.com` 至少绕开了这一条（GitHub Pages 服务器本身的快慢仍然要实测）。

**第 1/2/4 项就挂了的话别硬上**——告诉我，我们把国内表单服务改成主通道。

### 三、部署接口到 Cloudflare

```bash
npm i -g wrangler
wrangler login

cd worker
wrangler d1 create rsvp --location apac     # --location apac 不能省，否则库可能落在美东
# 把输出里的 database_id 填进 wrangler.toml

wrangler d1 execute rsvp --remote --file=./schema.sql

wrangler secret put ADMIN_TOKEN             # 32 位以上随机串，别用平时的密码
wrangler secret put IP_SALT                 # 随便一串随机字符，用来哈希 IP
wrangler secret put BACKUP_TOKEN            # 只对私有备份仓库有权限的 PAT（不备份可跳过）

wrangler deploy
```

再去 Cloudflare 控制台把 `rsvp.taolinwei.com` 作为 Custom Domain 绑给这个 Worker，
然后把这个地址填进 `index.html` 和 `admin.html` 的 `RSVP_ENDPOINT`。

验证：`curl https://rsvp.taolinwei.com/api/list` 不带口令应该返回
`{"ok":false,"error":"口令不正确"}`。

> **为什么必须用自己的域名**：`*.workers.dev` 在国内被 DNS 污染的报告很多，
> 而污染是按域名匹配的，用自己的域名正好绕开这一条；以后想换后端也只改一行。
> 别用 `.xyz`/`.top` 这类便宜后缀，在国内更容易被微信的域名管控拦下来。

### 四、每天自动备份名单

名单是这个项目里唯一不可再生的东西，所以 `worker/src/backup.js` 每天把它
提交到一个**私有**仓库（`wrangler.toml` 里的 cron 触发）：

1. 新建一个**私有** GitHub 仓库，确认真的是 private——里面有宾客姓名和饮食禁忌
2. 建一个只对这个仓库有 Contents 读写权限的 fine-grained PAT，
   用 `wrangler secret put BACKUP_TOKEN` 存进去
3. `wrangler.toml` 里把 `BACKUP_REPO` 填成 `用户名/仓库名`
4. 可选：`HEALTHCHECK_URL` 填一个 healthchecks.io 的地址，
   备份成功才会 ping，这样"密钥被吊销"会变成一条告警而不是静悄悄地什么都没发生

条数比上次少 2 条以上时会**拒绝**备份，避免用一份异常的数据覆盖掉好的备份。

## 查看名单（数据管理后台）

打开 `https://taolinwei.com/Wedding-Invitation/admin.html`，输入 `ADMIN_TOKEN` 设的口令，可以看到：

- **四个统计**：登记条数、出席总人数、平均每条人数、有备注条数
- **出席人数分布**：1–5 人各有多少条登记的横向柱状图
- **每日登记趋势**：按天聚合的累计折线图（登记满两天后才显示）
- **可搜索、可排序的名单表格**：支持按姓名/备注搜索，点表头按人数或时间排序
- **导出 CSV**：导出的是当前筛选结果，文件带 UTF-8 BOM，Excel 打开中文不乱码
- **「最近一条登记：X 天前」**：超过 7 天标红。每一种静默故障（接口挂了、额度用光、
  备用表单被暂停）在名单上长得都一样——没有新登记，所以要把这个显式显示出来
- **从备用通道导入**：把微信收到的「【出席登记】…」整行，或备用表单导出的 CSV
  粘进去，解析后确认再写回服务器。同名会标"疑似重名"且默认不勾选；
  没认出来的行会原样列出来告诉你，**不会悄悄丢掉**

口令只临时存在浏览器当前标签页，关掉即清空。页面加了 `noindex` 不会被搜索引擎收录，
但**知道网址的人仍能看到登录框**——口令用 32 位以上随机串，别用平时的密码，
它是保护两百来位宾客姓名的唯一一道门。
