# 婚礼请柬网站 · 陶林伟 & 肖佩韦

一个单页静态婚礼请柬网站，包含婚礼信息展示和出席登记表单。

## 页面内容

页面从上到下的顺序：

1. **婚礼请柬主视觉**：`images/invitation.jpg`，一张完整设计好的请柬图片（标题、新人姓名、
   日期、农历日期、签到合影/晚宴仪式时间、婚礼地址等信息都画在图里）。
   **可以点击放大**，页面也允许双指缩放，方便年长的宾客看清（页面上不作文字提示）
2. **出席登记表单**：姓名、是否出席、出席人数（下拉，最多 5 人）、备注
3. **走动动画**：手绘线条风格的小动画（详见下方"走动动画"）
4. **图片展示区**：婚纱照 + 中式礼服，点任意一张可放大查看，支持左右切换和 Esc 关闭
5. **页尾**：新人姓名与日期

> 页面**没有**禁用缩放（`<meta viewport>` 里不要再加 `user-scalable=no`），
> 否则年长宾客没法放大看细节。

## 走动动画

页面中段有一条手绘线条风格的小动画，四个角色会以不同速度、不同时间间隔循环走过：

| 角色 | 特征画法 |
| --- | --- |
| 英短蓝白 | 圆耳朵、身上一条分色曲线 |
| 新郎 & 新娘 | 新郎西装领结、新娘长发婚纱捧花，两人牵手 |
| 金吉拉白 | 身体轮廓带绒毛凸起、大圆眼睛、蓬松羽状尾巴 |
| 美短 | 额头 M 纹、身上虎斑条纹、尾巴环纹 |

实现要点（都在 `index.html` 的 `<style>` 与内联 SVG 里）：

- **图形**：纯内联 SVG 路径，没有外部图片。头部/身体重叠处用白色填充（`.fw` 类）遮挡后面的线条，
  避免出现接缝
- **走路**：每条腿是一个 `.leg` 路径，用 CSS `transform-box:fill-box` + `transform-origin:50% 0`
  让它绕"胯部"来回旋转；`.leg.b` 用反相的关键帧，形成左右腿交替的连续步态
- **其他细节**：尾巴摆动（`.tail`）、婚纱裙摆轻晃（`.skirt`）、整体上下轻微起伏（`bob`）
- **无障碍**：系统开启"减少动态效果"时，整条动画会自动隐藏

想调整节奏，改每个 `.sprite` 上的 `--dur`（走完全程的时长）和 `--delay`（出场延迟）即可。

## 微信分享卡片

分享链接到微信时会显示一张卡片，包含标题、描述、缩略图三部分，这些都在
`index.html` 的 `<head>` 里配置好了：

- 标题、描述在 `<head>` 的 `og:title` / `og:description` 里，改文案直接改这几行
- 缩略图是婚纱照裁出的脸部特写 `images/share.jpg`（400×400、约 21KB —— 图太大微信会直接跳过）
- 另外在 `<body>` 最前面藏了一张同样的图，因为有些抓取程序不读 meta，只取 HTML 里的第一张图

> **换域名后必须改**：`og:url`、`og:image`、`itemprop=image`、`link rel=image_src`、
> `twitter:image` 这几行写的是完整绝对地址。微信基本不认相对路径，域名变了就要一起更新。

需要知道的限制：微信对普通链接**并不保证**读取 og 标签，分享卡片是它自己的爬虫按
启发式规则生成的。想要完全控制标题/描述/图标，官方途径是接入微信 JS-SDK，
而那需要有公众号并配置 JS 安全域名。上面这些做法是把命中率拉满，但没法保证 100%。

微信抓取结果缓存较久。改完重新部署后卡片没更新的话，在网址后面加个参数
（比如 `?v=2`）换成一个"新链接"再分享，或者等缓存过期。

## 背景音乐

页面支持一首循环播放的背景音乐，右上角有开关按钮。

音频文件是 `audio/bgm.mp3`（新郎自己弹的钢琴录音，从视频里提取的音轨：
单声道 80kbps、2 分 58 秒、1.7MB；已剪掉录音开头 1.2 秒的静音和结尾的 App 水印语音，做过响度归一化，开头不做淡入，结尾留 1.5 秒淡出以免循环回头时爆音）。
想换曲子就替换这个文件；如果文件不存在，按钮会自动保持隐藏，页面一切正常。

几点需要知道的：

播放时机：

1. 页面主要内容加载完（`load` 事件）后才开始下载音频，**不与请柬图抢带宽**
2. 缓冲到能一口气播完（`canplaythrough`）时自动开始播，中途不会卡顿
3. 直接以 45% 音量起播 —— 曲子本身起音就很轻，不需要额外做渐强
4. 如果浏览器拦截了自动播放，则在访客**第一次轻触页面**时再尝试一次

- **浏览器普遍禁止无交互自动播放带声音的媒体**，这是硬性限制、绕不过去。
  **iPhone（Safari / 微信 iOS 版）一定不会自动播放**，必须等访客碰一下屏幕；
  微信安卓版走 `WeixinJSBridgeReady`，通常能直接自动播放
- iOS 还有一个坑：**用户交互之前根本不会缓冲音频**，所以 `canplay` 可能一直不触发。
  因此按钮默认就显示（只有确认文件加载失败才隐藏），交互监听也会一直保留到
  真正出声为止 —— 否则第一次轻触时音频还没就绪，那一次就白白浪费了
- 访客手动按暂停后，不会再被自动接管，除非他自己再按一次
- 循环播放，右上角按钮可随时开关
- 建议把 mp3 压到 3MB 以内（当前 1.3MB），否则移动网络下载很慢

> 目前用的是自己演奏的录音。需要留意的是，演奏录音归你，但**乐曲本身的版权仍属原作者**，
> 而这个页面是公开可访问的。婚礼请柬这种私人用途一般不会有人追究，但严格说属于灰色地带。

## 图片展示区

照片都放在 `images/gallery/`，按用途命名，**改图片只要替换同名文件即可**，
不用动 HTML：

| 文件 | 内容 |
| --- | --- |
| `pNN.jpg` | 婚纱照，共 22 张（`p00.jpg` 是首图，两人正面全身）。编号按显示顺序递增，但**中间有跳号**（删掉过一批照片，为避免和之前沟通时的编号对不上，保留了原编号没有重排） |

排版说明：

- 用 CSS Grid 两列排布，`index.html` 里每张图带一个比例类：
  `r32`（横 3:2）、`r23`（竖 2:3），`full` 表示跨满两列
- **横幅照片通栏，竖幅照片两两成对**，两者交替出现，避免一路平铺下来；
  另外挑了几张竖幅做通栏当视觉重点
- 编号大致等于显示顺序（有跳号），想调整顺序改 `index.html` 里 `<button class="tile">` 的排列即可
- 增删照片后要重新编排：横幅通栏、竖幅两两成对，两者尽量交替
- **加载策略**：不用浏览器原生 `loading="lazy"`（它会一次并发抓好几张），
  改成自建队列：同一时刻只下载一张，且始终挑文档顺序最靠前的那张，
  滚动到附近才排队（提前一屏）。图片写在 `data-src` 上，由 JS 赋给 `src`
- 加载失败会退避重试 3 次；仍失败就跳过，不会卡住后面的图
- 换了图但文件名不变时，**记得把 `index.html` 里的 `?v=` 版本号加一**，
  否则宾客手机上的缓存会一直显示旧图（曾经踩过：部分人看到的是旧的模糊版）
- 点任意一张会打开灯箱大图，可用左右箭头/键盘方向键切换，点背景或按 Esc 关闭

所有图片长边压到 1600px、质量 0.88（请柬图 1700px / 0.9）。

关于体积与带宽：全部看完 + 听音乐，单个访客最多下载约 **12 MB**。
按 300 位宾客算约 3.4 GB，只占 100GB 月流量的 3.4%（1000 人也才 11%）。
所以画质留了充足余量，不必为省流量牺牲清晰度；反过来，如果以后要再加很多照片，
可以按这个方法重新估算。
新加照片时建议也先压到这个量级，否则手机流量打开会很慢。

## 出席登记表单（存到 EdgeOne KV）

访客填完表单点"提交登记"后，请求发到 `/api/rsvp` 边缘函数，函数把记录写进
EdgeOne 自带的 KV 存储。**数据全程留在腾讯云内部**，不依赖任何第三方服务，
国内访客提交不用走跨境网络。

表单不再单独收集"是否出席"——提交表单本身就代表出席，`attend` 字段在后端
固定写成"出席"（不再从前端传入），后台名单和 CSV 导出也去掉了这一列。

- **新增**：第一次用某个姓名提交，新建一条记录
- **修改**：之后用同样的姓名再提交一次，会覆盖那条记录（不会产生重复），
  首次登记时间会保留
- 人数超出 1–5 会被自动收进范围，姓名为空会被拒绝

> 用"姓名"作为唯一标识。万一两位宾客同名，后填的会覆盖先填的。
> 如果担心重名，告诉我，可以改成"姓名 + 手机号"一起作为标识。

具体怎么配置见下方「部署结构」。

## 部署结构（重要）

页面和接口**分开部署在两个地方**，因为 GitHub Pages 只能托管静态文件、跑不了后端函数：

```
GitHub Pages                          EdgeOne Pages
https://www.taolinwei.com/            https://<你的项目>.edgeone.cool/
        Wedding-Invitation/                   └── api/rsvp   写入登记
        ├── index.html                        └── api/list   读取名单
        ├── admin.html          ── 跨域调用 ──▶
        └── images/
```

两边的连接点是 `index.html` 和 `admin.html` 里的 `API_BASE` 常量，填 EdgeOne 项目
的完整地址（结尾带斜杠）。**换了 EdgeOne 项目地址，这两个文件各改一行即可。**

### 一、页面部署到 GitHub Pages

1. 把分支合并到默认分支（`main`）
2. 仓库 Settings → Pages → Source 选 `main` 分支、目录选 `/ (root)`
3. 因为 `taolinwei.com` 已经绑在你的个人主页仓库上，本仓库会自动挂在
   `https://www.taolinwei.com/Wedding-Invitation/`
4. 仓库里的 `.nojekyll` 是为了让 GitHub 原样输出文件，不要删

### 二、接口部署到 EdgeOne Pages

保留现有的 EdgeOne 项目（它现在只负责跑 `functions/` 下的接口），并配置：

| 类型 | 名称 | 说明 |
| --- | --- | --- |
| KV 命名空间绑定 | `RSVP_KV` | 存登记数据，名字必须一致 |
| 环境变量 | `ADMIN_TOKEN` | 后台口令，自己定，别写进仓库 |
| 环境变量 | `ALLOWED_ORIGIN` | 填 `https://www.taolinwei.com`，限制只允许你的站点调用接口。不填则允许任意来源 |

配置完重新部署一次生效。

> 接口跨域是这套结构的必然产物，函数里已经处理好了 CORS（含 `OPTIONS` 预检）。
> 如果哪天整站都搬到 EdgeOne 上，把两个 HTML 里的 `API_BASE` 改成空字符串 `''`
> 就会走同源请求，不再跨域。

## 查看名单

打开 `https://www.taolinwei.com/Wedding-Invitation/admin.html`，输入 `ADMIN_TOKEN`
设的口令，可以看到：

- 登记条数 / 出席家庭数 / 出席总人数 三个统计
- 完整名单表格（姓名、是否出席、人数、备注、登记时间）
- 「导出 Excel（CSV）」按钮，文件带 UTF-8 BOM，Excel 打开中文不乱码

口令只临时存在浏览器当前标签页，关掉即清空。页面加了 `noindex` 不会被搜索引擎收录，
但**知道网址的人仍能看到登录框**——口令别设得太简单。
